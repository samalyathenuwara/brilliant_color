How it works

Each week you choose how many cases of BC-6 to order before you know what demand will be. This tool compares every choice by its expected profit: the average profit you'd earn if the same week repeated many times.

1. Profit for one order and one demand

You can only sell what you have, and only what customers want:

Cases sold = min(Order, Demand)
Profit = Price × Cases sold − Cost × Order + Unsold value × (Order − Cases sold)

Example with the defaults: order 300, demand 100 → sell 100. Profit = $100×100 − $25×300 = $2,500.

2. Expected profit for one order

Weight each demand scenario's profit by its probability and add them up:

E[Profit | Order] = Σ P(Demand) × Profit(Order, Demand)

This is the "chance node" in the decision tree: one branch per demand level.

3. Pick the best order

The "decision node" picks the order quantity with the highest expected profit. That's the recommendation, highlighted in green.

Using the inputs

  • Change price, cost or unsold value and everything updates at once.
  • Probabilities must add up to 1 (100%). Use Equal probabilities to split them evenly.
  • You can also change the demand levels and the three order options.

What it doesn't account for

Expected profit ignores risk: a bigger order can have a higher average but a worse bad week. Check the payoff table for the worst case of each choice. It also ignores lost goodwill from turning customers away.
